# Plot Workbench 三批更新计划

日期：2026-11-05。基线：已发布的 1.3.4。

用户决定将八项改进分为三个交付批次。本计划确定分工、依赖和验收范围；版本号在各批实现、验证与用户验收后确定，发布按 [updating.md](updating.md) 执行。

## 工作量分配

工作量为规划权重，用于比较各批规模，并非已经测量的工时或日历承诺。首次技术验证后可以细调权重，八项交付范围保持可追踪。

| 批次 | 对应建议 | 重点 | 工作量 |
| --- | --- | --- | --- |
| 第一批 | 1、2、3 | 文件位置、保存恢复、工作区布局 | 30% |
| 第二批 | 4、5、6 | 换数据复用、数据导入、模板与配色管理 | 35% |
| 第三批 | 7、8 | 论文导出、批量绘图、多子图排版 | 35% |

| 原建议编号 | 交付内容 | 规划权重 |
| --- | --- | --- |
| 1 | 文件位置说明与检查 | 8% |
| 2 | 可恢复草稿、保存状态与版本历史 | 12% |
| 3 | 首页与编辑工作区布局 | 10% |
| 4 | 保留样式、替换数据生成新图 | 15% |
| 5 | 更直观的数据导入和角色映射 | 10% |
| 6 | 模板与配色的检索、预览和分享管理 | 10% |
| 7 | 论文导出预设与检查 | 12% |
| 8 | 批量绘图和多子图排版 | 23% |

第三批虽然只有两项，但包含任务队列、失败恢复、图形组合和多格式输出，工作量与第二批相当。

## 第一批：文件位置、保存恢复与布局（1、2、3）

目标：用户清楚文件存放位置、当前保存状态，能够恢复编辑内容，并拥有更集中的绘图空间。

### 交付范围

1. 在设置中集中展示程序安装位置、模板与配色库位置、当前项目位置，并提供打开文件夹和检查入口。安装登记与实际程序不一致时给出具体原因。
2. 更换模板库时区分“切换已有库”和“迁移当前库”。操作前展示目标库概况；迁移前验证目标位置并保留可回退的原库。
3. 为工作台代码、数据选择与图内编辑补充可恢复草稿；统一“有未运行修改、运行中、已运行待保存、已保存、预览过期”等状态。
4. 将已有正式保存版本呈现为可浏览、可比较的历史，恢复操作生成新的版本或副本。
5. 保留绿白品牌，收紧首页统计与卡片；项目支持搜索、最近修改时间、缩略图、卡片/列表切换；侧栏支持折叠。
6. 以画布为中心整理编辑页面：属性在侧边，数据与代码按需展开；提供标准/紧凑密度，常用操作位置固定，禁用状态说明原因。

### 验收场景

- 首次使用、更换库、再次启动时，目录含义和现有内容数量清楚；取消操作不改变原库。
- 修改代码或数据后异常退出，重开可选择恢复草稿；恢复本身不执行代码，也不将草稿标记为已验证。
- 可以查看历史预览并恢复为新版本/副本，当前原件保持可追溯。
- 首页、代码/数据编辑、图内编辑和设置在常用窗口尺寸及 Windows 100%、125%、150% 缩放下可操作；关键操作不被遮挡，不出现非预期横向溢出。
- 从普通 Explorer 环境核对安装记录与程序位置，保留此前自定义安装目录的更新验证。

实施顺序：目录与状态模型 → 草稿/历史持久化 → 工作区布局与交互统一。

## 第二批：数据复用、模板与配色（4、5、6）

目标：一张调整好的图能够方便地换数据生成新图；模板和配色更容易选用、分享和复用。

### 交付范围

1. 增加“以此图为基础，替换数据生成新图”：选择新数据、确认角色映射、检查样式兼容性、预览、保存为独立新图。
2. 保留原图、原始输入与已有模板的独立快照。图内调整仅在可以正确重放和验证时沿用；不兼容项明确说明。
3. 数据导入增加点击/拖选行列、Excel 式列标、选区尺寸与异常单元格提示；现有精确范围输入及 `0 至 0` 规则继续保留。
4. 对标准模板提供横轴、纵轴、分组、误差列等角色映射，按列名和类型建议、由用户确认；普通 Python 脚本保留自由使用数据的方式。
5. 模板展示适用数据结构、示例、作者、版本和说明。分享包增加包内预览、选择导入和重复项处理，并兼容已发布 1.3.4 分享包。
6. 配色增加分类色、连续色和发散色的用途标记，以及灰度、色觉差异和实际图形中的预览。

### 验收场景

- 将一张已经图内编辑的图换成另一组兼容数据，得到可继续编辑的新图；原图、源文件与旧输出不变。
- 遇到列缺失、类型不匹配或无法沿用的图内调整时，预览前解释具体问题，不静默替换或丢弃数据。
- 同一套列映射和兼容判据供导入、模板匹配、换数据及后续批量绘图使用。
- 新旧版本 ZIP 分享包均能正确识别；选择性导入只保存被选项目，同名处理结果可预期。
- 配色预览不修改已保存图形；正式应用后仍按原有验证流程保存。

实施顺序：数据角色与兼容检查 → 模板元信息和样式快照 → 换数据生成副本 → 分享管理与配色预览。

## 第三批：论文导出、批量绘图与组图（7、8）

目标：从单图完成扩展到多组数据、一套论文图的重复生产和交付。

### 交付范围

1. 导出支持毫米/厘米图幅、保存和复用期刊预设，并明确格式、分辨率、背景及文件名。
2. 将字号、字体、裁切、图例遮挡等检查汇总到导出前界面；检查结果说明具体对象，区分阻断错误与建议。
3. 导出完成展示缩略图、实际尺寸和文件位置，并提供打开文件夹入口。
4. 基于第二批的数据映射和样式复用能力，选择多个文件或工作表，统一模板、命名与导出预设，先检查再批量生成。
5. 批量任务提供逐项进度、取消、失败原因、重试失败项和结果汇总；固定本次模板/样式版本，每张图独立验证和保存。
6. 基于已保存图形提供多子图排版：行列布局、对齐、间距、面板标号、统一字号和图例样式，支持 PNG、PDF、SVG 输出。
7. 共用图例仅在系列名称与样式对应关系可以验证时提供；不兼容时保留各子图图例并解释。组合结果保留子图来源与排版参数。

### 验收场景

- 同一图使用不同导出预设后，实际尺寸、字体与预览相符，既有 PNG/SVG/PDF 和代码包流程继续可用。
- 同一模板处理多个同结构工作表；单项失败不会覆盖既有成果，其余任务状态准确，可单独重试。
- 取消批量任务后，没有已标成功但缺失文件、半写入单图或来源不明的输出。
- 将四张已保存图排成 2×2，编号、间距、图例与图形内容正确，多格式导出可重新打开检查。
- 组图和批量结果可以追溯到模板版本、数据快照、样式设置与原始子图。

实施顺序：导出预设与检查 → 批量任务队列 → 多子图排版 → 多格式与复现验收。

## 每批共同的完成标准

- 直接在指定工作区的 `workbench/v1` 开发，保持用户数据和生成产物不入 Git。
- 用户现有项目、模板、配色及旧分享包保持兼容；目录迁移和恢复提供明确的回退路径。
- 会话认证、worker 边界与 prepare → verify → commit 不变式保持有效。草稿自动保存不绕过正式保存校验。
- 按改动运行相应后端、前端、生产构建和真实桌面流程验证；核心不变式用例按仓库要求手工反证。
- 发布验收包含普通桌面环境中的安装/升级核验，不能仅依赖维护宿主中的记录。
- 每批单独展示可运行成果、验收结果和已知限制；用户决定具体版本及发布后，再按既有流程准备并核验发行草稿。
